# 01 功能需求规格（PRD）

## 1. 目标与角色

目标：为家庭或小范围用户提供一个**训练后录入、持续观察、横向比较**的局域网健身管理系统；不是训练过程中的动作指导 App。PC 优先，手机兼容。

- **管理员**：首次初始化时创建；新增、启停普通用户、重置密码、系统备份恢复；管理员如需训练，可使用自己的普通用户能力。管理员身份不自动绕过其他用户隐私授权。
- **普通用户**：管理自己的计划、记录、体重、共享设置；查看其他**已授权**用户的统计汇总。
- **未登录访客**：只访问登录页及静态资源，不可读取 API 私有数据。

## 2. 导航信息架构

六个一级页面，PC 固定左侧导航、顶栏个人信息，手机采用收起导航：

1. **数据概览** `/dashboard`：个人本月训练次数、完成率、训练天数、最近体重；最近记录表、趋势摘要、补录快捷入口。
2. **健身计划** `/plans`：当前生效周计划表、每日动作编辑、计划复制/停用；月历中的临时替换/追加/休息；动作库入口。
3. **训练记录** `/records`：按日期选择对应训练任务、逐动作勾选、草稿自动保存、提交；无计划自主添加训练；历史检索和编辑。
4. **统计分析** `/statistics`：训练统计（周/月/90天/自定义、训练热力日历、次数、完成率、动作频次）；体重统计（新增/编辑/删除、目标、趋势）。
5. **多用户比较** `/compare`：排行榜（次数/天数/计划完成率/动作完成率），2~5 位授权用户的柱状/折线对比；按授权层级展示体重变化/原始曲线。
6. **系统设置** `/settings`：本人资料与密码、目标体重、共享授权；动作库管理；管理员用户管理、备份恢复与系统状态。

## 3. 功能要求（带 ID）

### 用户与安全

- `USR-01` 首次安装仅允许从本机环回地址初始化首个管理员；初始化后关闭初始化接口。
- `USR-02` 用户名唯一、密码哈希存储；账号停用后现有会话即失效。
- `USR-03` 登录/退出、修改个人密码；管理员创建用户并重置密码（重置后旧会话失效）。
- `USR-04` 服务端强制数据所属权校验；任何资源 ID 遍历不可越权。
- `USR-05` 共享开关默认为关闭；授权细节参照规则 `PRIV-*`。

### 健身计划与动作库

- `PLN-01` 每个用户同一时刻仅一套 `ACTIVE` 周循环计划，每周一到周日最多各一项训练安排（也可以是休息）。
- `PLN-02` 周计划可创建、编辑、复制、停用；动作支持力量/有氧/拉伸、自定义名称、目标组数/次数/重量或时间/距离。
- `PLN-03` 日期调整有 `REPLACE`、`ADD`、`REST`；独立于每周固定计划。
- `PLN-04` 月历可查看某天实际应执行的所有训练任务及来源；历史安排不因后来编辑而改变。
- `PLN-05` 动作库含系统预置与用户自定义动作；编辑历史引用动作不应变更历史快照。

### 训练后记录

- `REC-01` 以训练日期进入，加载当天已生成的计划任务；可选择计划外自主训练。
- `REC-02` 每个动作支持完成/未完成，允许用户执行顺序与列表顺序不同。
- `REC-03` 首次操作创建草稿；每次勾选自动写入草稿；刷新/切换设备后恢复。
- `REC-04` **手动提交**记录；0/部分/全部动作完成均可提交，完成结果计算见业务规则。
- `REC-05` 过去日期可补录；已提交记录可显式进入编辑状态并重新提交；保留修改时间/审计日志。
- `REC-06` 计划快照与历史记录不受后续计划或动作库改名影响。

### 统计、体重与比较

- `STA-01` 个人完成训练次数、训练天数、计划完成率、动作完成率、按动作统计、热力日历。
- `STA-02` 每个统计结果支持本周、本月、最近 90 天和指定日期区间；默认本月，日期用业务时区计算。
- `WGT-01` 体重记录日期/时间/重量 kg/备注；可补录、修改和删除；每日多条允许。
- `WGT-02` 目标体重可选；最新体重、阶段变化/变化率、每日最后一次体重趋势；不足两条有效记录展示“—”。
- `CMP-01` 训练汇总已授权用户参与排行榜；四项排行分别排序，不产生综合分。
- `CMP-02` 2~5 位获授权用户比较训练趋势；按体重变化授权展示变化汇总，按原始值授权展示体重曲线。
- `CMP-03` 比较采用同一统计区间；缺失数据不填零，体重变化不排名、不作健康评价。

### 运维与非功能

- `OPS-01` Windows 10/11 本机启动服务，同一局域网浏览器访问，无需用户电脑安装客户端。
- `OPS-02` 正常小规模用户（建议 ≤20 账户，日常并发 ≤5）可用；前端主要页面在常规局域网连接下交互流畅。性能基线见测试文档。
- `OPS-03` 备份/恢复包含数据库和系统配置；恢复需管理员二次确认；每日定时备份和保留策略。
- `OPS-04` PC 1366px 起完整操作、手机 375px 起可用且无关键横向溢出；键盘可访问。

## 4. 关键用户场景

1. 普通用户登录 → 建立每周周一胸部/周二背部训练计划 → 为下周五设置临时游泳 `ADD` → 月历见两场任务。
2. 周一训练结束 → 选择周一 → 勾选 3/4 动作 → 自动暂存 → 点击提交 → 状态“部分完成” → 统计更新。
3. 用户一周后将卧推名称或重量目标修改 → 上周训练历史显示原目标/动作名称。
4. 用户录入体重并设置目标 → 看近 30 天曲线；授权共享“变化量”但不共享原始体重 → 其他用户仅可见变化量/百分比。
5. 管理员创建第二账号；第二用户无法读取第一用户计划、草稿、体重或私有明细。

## 5. 用户可见状态

- 计划：草稿 `DRAFT`、启用 `ACTIVE`、停用 `INACTIVE`。
- 日期安排：计划训练、临时替换、临时追加、休息。
- 训练记录：未录入（无 session）、草稿 `DRAFT`、已提交 `SUBMITTED`；已提交结果为全部/部分/未完成（按完成动作数推导）。
- 页面请求：加载中、成功、空状态、校验失败、网络错误；不得用空数据伪装网络错误。

## 6. 非目标与产品取舍

训练记录是**训练后的事实记录**：支持同一动作下逐组填写结构化次数/重量（或时长/距离）并勾选完成，不实现训练过程计时或实时运动提醒。计划模板同样以「动作 → 多组」编辑目标。体重变化不直接等同于健身效果。训练排行榜仅展示汇总指标，不展示他人动作明细。
