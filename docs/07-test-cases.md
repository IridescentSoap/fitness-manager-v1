# 07 测试与验收用例

## 1. 测试类型与要求

- 后端单元测试：计划解析、冻结/覆盖、训练提交、统计计算、体重聚合、共享鉴权。
- API 集成测试：真实 SQLite 测试库 + HTTP 客户端 + 两个普通用户和一个管理员；不得用 mock 代替权限测试。
- 前端组件/交互测试：表单校验、保存反馈、空状态、移动端响应式。
- E2E：Playwright 真实浏览器覆盖登录、创建计划、补录、统计、比较、共享撤销、备份恢复。
- 测试必须隔离数据、可重复运行；测试用户的密码和 Cookie 不写入日志。

## 3. 固定统计测试数据样例

测试日期统一在业务时区、同一统计区间（且都已到期）：

- 计划任务 P1：4 个动作，提交 4/4 → `FULL`。
- 计划任务 P2：4 个动作，提交 2/4 → `PARTIAL`。
- 计划任务 P3：2 个动作，无提交 → 仍计入 `P_due`。
- 当天额外 AD_HOC：3 个动作，提交 3/3。
- P1、AD_HOC 同一天；P2 另一天；P3 再另一天。

**预期：**

- `P_due=3`、`P_full=1`、计划完成率 `33.33%`（精度两位）。
- 计划动作完成率 `(4+2+0)/(4+4+2)=60%`。
- 完成训练次数 `3`（P1、P2、AD_HOC 均至少完成一个动作）。
- 实际训练天数 `2`（P1 与 AD_HOC 同一天）。
- P3 是未开始但应执行计划任务，不能被忽略；AD_HOC 不影响计划分母。

## 4. 安全与鲁棒性测试

- 同一 cookie 修改 URL 中资源 ID 越权，返回 404；管理员也不能据此获取未授权体重。
- POST 无 CSRF、错 CSRF、跨域非法 Origin → 403；重复登录失败 → 429。
- SQL 注入、不合法日期、无效 Decimal、空动作提交、负数重量/次数 → 422 或拒绝，不污染 DB。
- 网络断开勾选时 UI 显示“保存失败”，恢复网络后可重试，不应错误提示保存成功。
- 数据库断电/进程中断之后 `integrity_check=ok`（在正常操作约束下）；备份测试包含 WAL 写入期间一致性。
- 原始体重撤销后，其他用户再请求比较接口不能命中缓存旧数据；所有敏感响应 no-store。

- `pytest` 后端关键规则与鉴权自动化全部通过；API OpenAPI 与契约样例匹配。

- Windows 实机按文档从空环境可启动，局域网另一台设备可登录（清单：`docs/08-windows-acceptance.md`）。
