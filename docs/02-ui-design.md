# 02 PC 优先 UI/UX 与交互规范

## 1. 设计语言

**清爽训练室**：浅色优先、留白与细线层次；深色为夜间克制版。橙色强调保留，避免厚重玻璃与大阴影。示例设计令牌（以 `frontend/src/styles/tokens.css` 为准）：

```css
:root {
  --bg: #f7f8fa; --surface: #ffffff; --surface-alt: #f3f5f8;
  --accent: #e25b2a; --accent-hover: #f06a38;
  --text: #1c2430; --text-muted: #667585; --border: #e4e8ee;
  --radius: 10px; --control-height: 40px;
}
```

- 数据颜色不要只依靠颜色区分；须附图例/数字/状态标签。字体以本机字体为主（Segoe UI / Bahnschrift + 苹方/微软雅黑），不依赖外部 CDN 字体。
- 图表图例、坐标轴、悬浮提示随浅/深色主题切换；体重等敏感信息不可在未经授权的对比图上泄露。
- 侧栏/顶栏精致轻量；面板、按钮、表格统一间距与控件高度；表格与分析以可读性优先。

## 2. 响应式布局

- PC 设计基准 1440×900；支持 1366px 及以上。固定左侧导航 220px（可折叠至 64px），顶部栏 64px，内容区最大宽 1600px，页面边距 24px。
- `>=1200px` 4列核心指标卡、图表双列；`768~1199px` 2列；`<768px` 导航折叠为抽屉，卡片单/双列，表格切换卡片或可控横向滚动，关键操作无横向溢出。
- 手机优先保留浏览/补录/打卡功能完整性；宽幅对比图表可切换单图展示。

## 3. 全局框架

- 顶部：页面标题、面包屑（非首页）、当前登录用户、退出。显式显示当前用户，避免同设备多人误录。
- 左栏：`数据概览/健身计划/训练记录/统计分析/多用户比较/系统设置`。活跃导航高亮橙色侧线。
- 全局状态：Skeleton 加载、空状态（提供明确操作）、Toast 成功、含重试按钮错误状态、重要破坏性操作二次确认。
- 所有日期控件使用业务时区 `APP_TIMEZONE`，日期显示 `YYYY-MM-DD`，录入时不能仅依赖浏览器本地日期。

## 4. P01 数据概览 `/dashboard`

PC 页面：标题与当前统计区间 → 四张 KPI 卡（完成训练次数、计划完成率、训练天数、最新体重）→ 左侧每周训练次数图 / 右侧近期体重曲线 → 最近 10 条记录表（日期、训练主题、完成情况、编辑）。

- 主要 CTA `补录训练` 跳至 `/records?date=today`。
- 所有 KPI 可点击跳转对应统计页，带同一区间筛选。
- 无体重数据提示“尚未录入体重”，不要显示 `0kg`。

## 5. P02 健身计划 `/plans`

- 顶部：当前启用计划名/生效区间/状态；按钮 `新建计划`、`复制`、`停用`。
- 视图切换 `周循环 / 月历`。周循环表列：星期、训练主题、动作数、是否休息、操作；每行“编辑”打开右侧 480~560px 抽屉。
- 抽屉：训练日名称、是否休息、动作列表（上下移动）；每项动作下嵌组表（力量：次数/重量；有氧/拉伸：时长/距离），可添加/删除组，新组默认复制上一组。保存写回计划模板，ACTIVE 计划仅重建今天及未来未提交任务。
- 月历点击某个日期，在右侧查看当天任务卡和 `替换/追加/设为休息`；操作时醒目说明“覆盖仅此日期，不改变每周模板”。
- 当更改会冲突已录草稿/历史时，显示 409 冲突说明；不允许悄悄覆盖已提交记录。
- 首次无计划空状态提示“创建你的第一份每周计划”。

## 6. P03 训练记录 `/records`

**核心使用模式：训练结束后记录，取消开始/结束训练按钮。**

- 左侧约 280px：日期选择器、当天任务列表（BASE/EXTRA/自主训练）、近 14 天记录快速入口；右侧：所选任务详情表。
- 任务详情：名称/日期/来源/当前草稿状态；动作可展开组表。列：`动作勾选(全选组) | 动作 | 类型`，组行：`组勾选 | 组序号 | 次数/重量或时长/距离`。
- 勾选组或改组数值自动写入草稿；动作勾选映射全部组；界面显示 `正在保存... / 已保存 / 保存失败`。
- 底部固定操作区：完成组数、进度条、`提交记录` 主按钮；提交 0 组时二次确认“确认提交未完成记录？”。
- 用户点击 `添加自主训练` 可以录入该日期额外动作，不改变计划执行分母。
- 过去已提交记录只读；按钮 `编辑历史` → 确认撤回为草稿 → 修改 → `重新提交`，并显示原记录提交时间与修改时间。
- 后端 version 冲突提示“该记录已在其他设备更新”，提供刷新，不覆盖别的设备修改。

## 7. P04 统计分析 `/statistics`

子页签 `训练统计` / `体重管理`：顶部统一日期选择 `本周/本月/最近90天/自定义`。

训练：KPI（训练次数、天数、计划完成率、动作完成率）；近12周训练次数趋势柱图、各训练类型/动作频次图；训练日历热力图；表格明细可穿透到本人的历史记录。

体重：KPI（最新、区间变化 kg/%、目标）；体重趋势折线图（缺测断点）、新增记录按钮；明细表支持编辑/删除（删除需要确认）。同日多记录可展开，默认趋势采用最后一次测量。录入表字段：测量日期、时间、kg、备注。无目标时显示“未设置目标”。

## 8. P05 多用户比较 `/compare`

PC 大屏结构：筛选区（日期区间、最多5个用户）、四项排行 Tab 与排行榜表、对比 KPI 表、分组柱图（次数/完成率）、折线图（周训练次数），体重图另设权限感知区。

- 排名切换：`训练次数/训练天数/计划完成率/动作完成率`；并列排名须一致；未知分母显示“无数据”，不混入有效排名。
- 用户选择下拉只出现对应已授权的账号；选中者撤销权限时自动从图中移除并提示。
- 体重变化卡需有 `share_weight_change=true` 才显示区间变化 kg/%；原始体重曲线需 `share_weight_values=true`，不可由体重变化授权推导原始体重。
- 体重数据图下注明“变化仅作数据对比，不代表训练效果优劣”。
- 无人开放授权时显示说明与自己可前往 `/settings` 开通的入口，而不是空白图。

## 9. P06 系统设置 `/settings`

普通用户：账户名、修改密码、目标体重、共享数据设置（训练汇总 / 体重变化 / 体重数值三个独立开关；默认关闭）、动作库（自己的自定义动作）。开启体重数值授权需弹窗说明“他人可推导你的体重变化”。

管理员额外面板：用户创建、启停、密码重置、备份列表/手动备份/恢复、服务版本与数据库状态；恢复必须二次确认且提示可能覆盖现有数据。管理员不可通过用户管理页面查看他人的私人体重和训练明细。

## 10. UI/交互验收

- 1366px PC：侧栏/图表/表格无重叠、主路径操作无需水平滚动。
- 375px 手机：能登录、查看计划、打卡提交、录体重、查看排行及调整共享。
- 关键操作键盘可达、有明确聚焦状态；复选框标签可点击；所有加载/成功/失败状态有可见反馈。
- 个人数据隐私配置默认为关闭，不能在初次打开对比页面闪现他人体重。
